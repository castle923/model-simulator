# 사용자 지정 기체 통합 독립 검토

검토자: agent20. 범위: 복사본 mechanic-hub의 사용자 지정 기체 공통 스키마, Free Space 실행, 소형 공장 연결, 커스텀 UI 및 합성 표시. 제품 코드는 읽기만 수행했으며 수정은 담당 구현자에게 요청했다.

추가 범위: TurtleBot3 Burger/Waffle Pi/원형 AMR, 선택적 bodyShape와 호환성, 설치 카메라 표시 연결. 카메라 패널의 최종 검토 상태는 아래 및 최종 검증 기록에 따른다.

현재 판정: **APPROVE — 검사된 소스·시뮬레이션 실행·모의 UI 범위**. 최종 실행 검사는 2026-10-16T09:28:26.312Z이다. 30개 테스트 스크립트와 TypeScript 검사 모두 통과했고 44개 대상 파일의 SHA-256이 검사 중 유지됐다. 이후 안내 문서 `docs/ROBOT_STUDIO.md`를 읽고 해시에 포함해 최종 목록은 45개이다. 공개 배포·실제 브라우저·실물 장비 승인을 뜻하지 않는다.

이전 APPROVE는 주 에이전트의 실제 UI 검증에서 입력 단계가 허용한 22×12m 지도를 하위 planner가 거부하는 문제가 발견되어 무효화했다. 기존 독립 경계 검사는 validateScene만 확인했고 해당 지도 크기의 실제 planScene을 실행하지 않아 이 문제를 놓쳤다. 이번 재승인에는 수정된 planner의 실제 경로 생성 및 전체 실행, 새 작업 공간 설정, 명시적 강제 실험, 지도 확대·이동·집중 화면이 포함된다.

추가 자유도 범위: 지도 2~30m, 최대 8대와 자동 충전 대기점, 경유지 40개, 목표에서 완료하는 stay 옵션, 버전이 지정된 고급 임무 JSON. 소형 공장은 기존 3×2m/24cm/4대 실험으로 유지된다.

최종 상태와 정확한 검사 대상 SHA-256은 `outputs/agent20-custom/verification.json`에 기록한다. 테스트 도중 해당 소스가 바뀌면 검증기는 실패한다. 이 문서만으로 배포/브라우저/실물 검증을 주장하지 않는다.

## 발견 및 수정 확인

- 엘리베이터 도착 층의 기존 고정 0.5m 검사에서 0.9×0.7m 기체 두 대가 0.8m 간격으로 겹쳐 하차했다. 담당자가 기체별 반경 합계와 여유로 변경했다. 독립 반례는 하차 대기를 확인한다.
- 공통 외형 함수의 픽셀 최소값이 Free Space의 미터 좌표에 적용되어 카메라·팔 끝점과 선이 지나치게 커졌다. 담당자가 모든 도형·선 굵기를 전달된 크기에 비례하도록 변경했다. 독립 mock Canvas 검사에서 미터/100배 좌표의 기하가 정확히 같은 비율로 변한다.
- 돌출된 카메라가 Free Space 안전 외곽에 포함되지 않았다. 담당자가 활성 장착 카메라의 외곽을 반영했다. 지도 밖 카메라와 가장 큰 허용 몸체의 렌즈 외곽을 독립 검사한다.
- 선택 카메라 ID가 다른 기체 또는 새 구성에 남아 활성 카메라가 없는 것처럼 표시할 수 있었다. Free Space 및 소형 공장의 누락 ID 초기화와 공장 렌더링의 안전한 기본 선택을 소스로 확인했다. 실제 UI 전환 검사는 주 에이전트 담당이다.
- Free Space 적용이 commit 결과와 무관하게 성공을 반환하던 구조를 담당자가 실제 commit 결과 반환으로 변경했다. 초기 저장 지도 로딩 전에 기본값이 저장될 수 있던 흐름에는 준비 상태/저장 허용 검사를 추가했다. 이 항목의 실제 브라우저 저장소 회귀 검사는 주 에이전트 담당이다.
- stay 기체에 안전모 임무를 적용하면 이전 stay 정책이 남아 검증에 실패했다. 담당자가 charge로 명시적으로 전환하고 최종 장면을 검증하도록 수정했다. 독립 전환 반례가 통과했다.
- 장치 목록 조회 실패가 실제 스트림을 유지한 채 오류 상태로 바꾸고 영상/종료 버튼을 숨기는 경로를 발견했다. 장치 목록 메시지를 연결 상태와 분리한 수정 후, 모의 React/MediaStream 테스트에서 영상과 종료 버튼이 유지됨을 확인했다. 첫 연결 초기화도 layout effect 실행 순서를 반영해 검증했다.

## 재현 가능한 검증

`node research/agent20-custom/verify-final.mjs`는 현재 30개 테스트 스크립트와 TypeScript 검사를 실행한다. 이번 기록은 09:25:29Z의 27개 스크립트+TypeScript 전체 통과와 마지막 UI 수정 3개 파일에 대한 09:28:26Z의 표적 재검증을 결합했다. 마지막에 추가된 세 검사는 구현자의 실험 명령 회귀 및 독립 Operator/RobotCode 모의 UI 검사이다. 최종 표적 검증은 작업공간 통합·실험 UI·코드 UI·명령 검증·Worker 바이트 일치·TypeScript를 실행했고, 나머지 소스는 이전 전체 검사 해시와 같음을 확인했다. `finalize-review.mjs`는 이 마지막 상태 전이를 기록한 일회성 검사이며 전체 재실행에는 `verify-final.mjs`를 사용한다.

- 공통 사용자 지정: 프리셋, 엄격한 JSON 검증, 이전 구성, 치수·팔·카메라 반영, 기체별 속도, 이종 기체 안전, 층 이동.
- 소형 공장: 복수 적용 실패 원자성, 위치/시간/프로토콜 보존, 설정 왕복, 24cm 통로 거부, 접힌 팔, 작업 중 거부, 서로 다른 속도의 4대 완주.
- 기존 장면/동적 주행/소형 공장 실행·통신/전면 투영/코드 내보내기 안전/이전 Astra 연속 충돌 검증.
- 독립 반례: 잘못된 중첩 스키마, 마지막 대상 오류로 인한 전체 취소, 입력과 저장 구성 분리, 큰 기체 하차 충돌, 돌출 카메라, 정면·후면 합성 감지, 카메라 비활성화 후 초기화, 렌더링 축척 불변성.
- 혼합 기체 전체 실행: 초기 지도에서 R1 명목 라즈봇·속도 0.12m/s·정면/후면 카메라·접힌 양팔, R2 0.6×0.45m AMR·속도 0.28m/s를 적용한다. 임무/충전/이탈 완주까지 프레임별 정적 장애물 이동 구간, 기체 간 여유, 개별 속도 상한을 검사한다.
- 추가 혼합 구성도 완주했다: Burger+원형 AMR 81.36초 / 최소 간격 0.555135m, Waffle Pi+AMR 69.66초 / 최소 간격 0.756620m. 기존 schema1의 bodyShape 없는 구성은 보존되고 잘못된 shape는 거부된다.
- 6종×직사각형/타원형의 공통 외형에서 미터/100배 좌표의 선·원·타원·도형·이동 축척을 독립 비교했다.
- TurtleBot3 프리셋의 기본 치수·속도와 Burger 기본 카메라 없음은 [ROBOTIS 공식 사양](https://emanual.robotis.com/docs/en/platform/turtlebot3/features/)을 현재 확인했다. 절차적 그림은 제조사 CAD가 아니며 센서 구동을 뜻하지 않는다.
- 설치 카메라 연결 제어기는 가짜 MediaStream으로 독립 검사했다. 자동 획득 없음, 같은 R1의 작업 공간 변경 후 늦은 스트림 폐기, 역순 응답의 최신 연결만 유지, 연결 해제/컴포넌트 종료 중 보류 응답의 모든 트랙 종료, 장치 종료 처리, 권한 거절 안내, 이전 기체의 오류가 새 상태를 덮어쓰지 않음을 통과했다. 실제 USB 장치를 열거나 영상 프레임의 품질·동기화를 검증한 결과는 아니다.
- 8종 혼합 기체가 충전 예약 없이 각자의 목표에서 70.425초에 완료했다. 9번째 추가 거부, 고유 ID/대기점, 40개 경유지 경계, 오래된 고급 JSON 버전 및 13가지 잘못된 명령의 원자적 거부를 확인했다.
- 배포용 public/scene-worker.js는 현재 소스를 메모리에서 빌드한 결과와 바이트 단위로 일치했다. 이 검사에서 제품 파일을 쓰지 않았다.

## 재승인 확장 검토

- 하위 planner의 30m/반경 4m 수정 후 실제 routeLeg → planScene → stepSimulation을 독립 실행했다. 2×2m/경유지 40개는 37.75초, 22×12m 기본 두 기체의 충전 임무는 22.20초, 30×30m/최대 차체+펼친 팔/반경 2.76m의 벽 우회는 21.50초에 완료했다. 모든 이동 구간의 정적 장애물 여유를 확인했다. 반경 4m 직접 경로와 범위 밖 거부도 실제 planner로 검사했다.
- SceneLab 자체를 React/Worker/localStorage 모의 환경에 묶어 작업공간 콜백을 실행했다. 화면 설정 변경은 저장 지도와 Worker 호출 수를 바꾸지 않았고, 정사각형 캔버스 및 편집 패널 제거를 확인했다. 저장 실패는 실패 응답을 반환하고 테마를 유지한다. 잘못된 축소는 원자적으로 거부되며 22×12m 변경은 실제 경로를 생성한다. 빈 공장은 사용자 지정 기체 및 기반 시설을 보존하고 안전모 임무/대상을 제거하며 되돌리기/다시 실행으로 전체 객체·임무를 복원한다. 잘못된 저장 설정 원문은 유지된다. 브라우저 외관 검사는 별도이다.
- 사용자 요청의 명시적 강제 직선 실험 코어를 독립 검사했다. 40개 벽을 의도적으로 통과하며 지도 경계·속도는 유지했고 고유 안전 외곽 접촉 기록은 32개로 제한됐다. 같은 지도의 일반 모드는 경로가 없음을 반환한다. 새 기체 추가는 강제 실험 권한을 상속하지 않고 원래 car 모델을 복원한다. 정상 복귀·고급 임무·기체 코드·안전모 임무는 실험 플래그를 제거한다. 원래 car 모델을 복원하고 입력 장면은 변경하지 않는다.
- 자연어 파서가 “충돌을 허용하지 않고/말고”, “오류를 무시하지 말고”와 R10 명령을 강제 실행으로 해석하는 반례를 발견했다. 수정 후 이 표현들은 거부되며 명시적 긍정 명령과 정상 복귀만 지원 범위에서 처리한다. 이는 규칙 기반 문법이며 일반 자연어 이해 능력이 아니다.
- 모의 Operator UI에서 코드 생성만으로 적용되지 않고 명시적 적용이 필요함을 확인했다. 정상 복귀 후 저장 이력에 이전 force JSON이 남던 오류는 담당자가 실제 raw 명령을 기록하도록 수정했다. 정상 복귀 이력의 mode=normal, 거짓 성공 응답 방지, 실패 시도 기록을 재검증했다.
- 모의 RobotCode UI는 강제 실험 상태에서도 오류 없이 안내를 표시하고 일반 Python 미리보기를 숨긴다. 강제 실험 중 다운로드는 파일을 생성하지 않는다. 검증된 일반 코드 적용은 실험을 해제한다. SceneLab 실행 기록에는 접촉 ID·위반 메시지·개수가 저장되고 상태에 안전 성공 판정 제외가 표시된다.
- 지도 확대·선택 기체 초점·Shift 이동은 장면을 바꾸지 않았다. 확대·이동 뒤 화면 좌표로 R1을 드래그하면 정확히 세계 좌표 +0.3m 이동했다. 집중 화면 전환은 표시 속성만 바꾸고 장면을 유지했다. 모의 컴포넌트 검사이며 픽셀 외관·휠 UX·반응형 레이아웃은 주 에이전트 브라우저 검증 범위이다.
- 마지막 지도 문자 크기의 zoom 역보정 및 R1 이름 위치 역보정을 소스로 확인했다. 해당 SceneLab 해시는 최종 표적 검증 해시와 이미 같았으며 추가 경로·좌표 변경은 없었다. 최신 사용 안내의 실험 경계·32개 접촉 한도·50개 시도 이력·8대 혼잡 충전 미완주 설명을 검토했다.

## 검증 경계

- 브라우저 조작, 사용자 저장 지도 접근, 원본 프로젝트 수정, Git 작업, DB 연결, 클라우드 변경, 배포는 이 검토자가 수행하지 않았다.
- 합성 감지는 2D 수평 위치·방향·화각·거리·가림 기준이다. Z/pitch는 화면 투영에 반영되지만 3D 센서 검출을 증명하지 않는다.
- 팔 관절/도달 범위/하중은 가상 설정이다. IK, 물리 동역학, 실제 집기, 모터/제어기, 실물 가반하중을 검증하지 않았다.
- Free Space는 보수적 원형 외곽을 사용한다. 가능한 모든 사용자 지도·혼합 기체의 완주를 보장하지 않는다. 공장 통로는 24cm로 고정되며 모든 프리셋을 수용하지 않는다.
- 구현자 및 주 검토자의 22×12m 혼합 8대 충전 시나리오에서는 600초 후 6대 완료, R5/R8 충전소 접근 안전 대기가 보고됐다. 이 검토자의 8대 stay 완료 결과를 해당 혼잡 충전 시나리오의 완주 증거로 사용하지 않는다.
- 강제 직선 실험은 충돌을 의도적으로 허용하는 웹 실험이다. 기록은 보수적 안전 외곽과의 접촉이며 실물 충돌·물리학·안전 운행 증명이 아니다.
- 공개 페이지 반영과 실제 브라우저 결과는 주 에이전트의 별도 증거가 필요하다.
