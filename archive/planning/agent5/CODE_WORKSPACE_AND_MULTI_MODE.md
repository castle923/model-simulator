# 기체 코드 공간·다중 전환 수정 인계

2026-10-14. 복사본 로컬 구현만 수행했다. 원본·운영 사이트·DB·push·배포 및 사용자 편집 탭은 변경하지 않았다.

## 파일 작성권과 통합

- 11번: 새 `app/RobotCodeWorkspace.tsx`, `lib/robot-code-export.ts`, 전용 export 검사. 기존 임무 파서/UI의 소유권은 11번에게 있다.
- 5번: `SceneLab.tsx`·공통 CSS에 코드 공간을 배터리 카드 바로 아래 좌측 공백에 통합하고, 상단 사용 방법 모달 버튼을 추가했다. `scene-local.ts`의 spawn 함수와 다중 전환 UI만 공통 제품 수정했다.
- 코드 패널은 현재 관찰 기체 ID·scene·poses를 props로 받는다. 카드/관찰 기체 전환과 코드 대상이 일치하며 안전모 소유권도 동일 runtime에서 표시한다.
- JSON은 검증된 `applyRobotProgram` 또는 기존 `applyMission` 흐름을 통해 실제 웹 명령으로 적용한다. Python·Notebook은 같은 검증 명령과 상태 스냅샷을 설명하는 dry-run이며 웹 TypeScript 런타임 원본이나 실물 제어 코드가 아니다.
- 파일 형식 선택 다운로드와 `read.md`, Python `#` 주석, JSON 별도 필드 설명을 제공한다. JSON에 `#`는 허용하지 않는다. `.ipynb`가 올바른 Notebook 확장자다.
- 실제 카메라/PPE 클래스·미착용 판단·track ID↔지도 ID 결합·Pi5 전달은 미연결 또는 명시적 `NotImplementedError`다. 기본 Python 실행은 표준 라이브러리 단계 출력만 하며 실제 카메라·모터를 시작하지 않는다.

## 다중 전환 원인과 수정

사용자의 실제 지도 v80에서 기존 R1 출발은 `(1,1)`이었다. 고정 추가 위치 `(.65,1.25)`는 기체 간 거리 약 0.430m로 최소 0.5m 검증을 위반하여 추가가 거절됐다. select 값은 실제 기체 수에서 유도되므로 다시 단일로 보였다. 이는 별도로 표시된 자동차식 U턴 경로 불가 문제와 다르다.

새 `addSceneRobot(scene,floor)`는 단일→다중 첫 추가에서 기존 기체 반대편의 빈 출발/목표를 우선 고려하고, 이후에도 장애물·사람·안전모·기존 기체를 피하는 빈 위치를 검색한다. 실제 반례에서는 `(8,2.5)`를 선택해 기존 R1과 약 7.159m 거리를 확보했다. 기존 기체/지도는 수정하지 않고 새 기체의 임무는 navigate로 초기화하여 기존 전달 임무를 복제하지 않는다.

빈 출발/목표가 없으면 구체적인 전환 불가 이유를 표시하고 기존 구성을 유지한다. 실행 중 구성 변경 잠금과 일시정지 후 전환 방법도 표시한다. 전환 성공 뒤에도 자동차의 최소 반경·장애물 경로가 불가능하면 Worker가 주행을 차단하며 두 사유를 혼동하지 않는다.

## 검증

- `test-robot-spawn.mjs`: 실제 R1=(1,1) 반례, 장애물 점유, 기본 4대 추가 후 임무 완료, 빈 공간 없는 지도에서 원본 보존·이유 있는 거부 통과.
- 기존 `test-carried-helmet.mjs`, `test-vibe-mission.mjs` 회귀 통과. vibe 검사는 이전 외곽 접근 기대를 유지하고 센터 접근으로 원복하지 않았다.
- 최종 통합 타입 검사와 `npm run build`(Worker 재생성 포함) exit 0. 11번 export 전용 검사 및 Python dry-run/AST·JSON 동일성·Notebook source 검사 통과. 6번 독립 검증·root 화면 검증은 각 담당의 최종 증거에서 확정한다.
- 6번 추가 반례 두 건을 수정했다. (1) 단일에서 3번 추가하는 1→4의 출발 경로 상호 차단은 첫 추가를 반대편에 배치해 완주하도록 수정했으며 1→4와 2→4 모두 114.20 시뮬레이션 초에 완료했다. (2) 가져온 ID 개행이 Python 주석을 벗어나던 문제는 고정 첫 두 줄·동적 주석 한 줄 escape·안전 파일명·scene ID 제어문자 거부로 수정했다. 악성 샘플은 실행하지 않고 AST로만 최상위 실행문이 생성되지 않음을 검사했다. 가져온 지도 검증 실패 원문은 기존 복구 JSON 정책으로 보존한다.
- 마지막 반응형 CSS 보강: grid/flex 자식 최소폭 0, 단일열 minmax, 긴 ID 줄바꿈과 코드 내부 스크롤을 적용했다. root의 명시 viewport 검증에서 995px(page/body 980px)와 650px(page/body 635px) 모두 전체 가로 넘침 없이 다운로드 버튼이 화면 안에 표시됐고 다운로드 동작도 확인했다. 좁은 화면의 코드는 상자 안에서만 가로 스크롤한다. 원래 캡처 당시 창 폭 변화가 있었으므로 모든 일반 폭에서 문제가 발생했다고 확대 해석하지 않는다.

코드 다운로드가 실제 Unity/CARLA/Gazebo·Pi5 연결 또는 PPE 자동 판정의 완료를 의미하지 않는다. 이번 변경도 배포하지 않는다.
