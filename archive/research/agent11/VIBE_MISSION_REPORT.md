# 11번 · 바이브 배치와 기체 임무 코드 분리

작성: 2026-10-14. 작업 범위: 메카닉 (2) 로컬 복사본만. 원본·배포 사이트·운영 DB·Pi5는 변경하거나 연결하지 않았다.

| 항목 | 구현 내용 | 이용 방법 |
|---|---|---|
| 바이브 배치 | 객체 생성만 수행하며 기체 임무는 변경하지 않음 | 작업자·안전모 등을 배치하고 지도에 적용 |
| 바이브 임무 | 자연어 입력을 제한된 전달 임무 JSON으로 변환 | 별도 ‘바이브 임무 코드 작업 공간’에서 입력 |
| 적용 기체 | 현재 R1~R4 목록과 동기화 | ‘임무 적용 기체’ 선택 후 생성·검증 |
| 정확한 대상 | 작업자·안전모 ID를 해당 기체에 저장 | 번호나 목록으로 픽업·전달 대상 선택 |
| 코드 편집 | JSON 직접 수정·유효성 검사 | 수정 후 ‘작성한 임무 코드 검증’ 클릭 |
| 적용·실행 | 선택 기체 임무만 변경, 경로·예약 초기화 | 적용 → Worker 검증 통과 → 주행 시작 |
| 대상 보호 | 모호성·대상 삭제·잘못된 종류·층 불일치·오래된 지도 코드 거부 | 메시지에 맞게 대상 선택 또는 코드 재생성 |
| 외형 표시 | 지도에 작업자·안전모 번호도 표시 | 임무 목록 번호와 지도 라벨 대조 |

## 예시 사용 순서

1. 바이브 배치 공간에서 ‘작업자 1명, 안전모 1개’를 생성하고 적용한다.
2. 바이브 임무 공간에서 R1 또는 원하는 기체를 고른다.
3. ‘작업자 1번이 안전모를 착용하지 않았으니 안전모를 픽업하여 보호장구를 착용하지 않은 작업자 1번에게 전달해줘’를 입력한다.
4. 안전모가 여러 개면 픽업 대상을 선택하거나 문장에 ‘안전모 2번’처럼 쓴다.
5. 자연어 → 임무 코드 생성 후 기체·안전모·작업자 ID를 확인하고 적용한다.
6. 경로 검증이 끝나면 주행 시작을 누른다. 안전모 집기 → 작업자 전달 → 기존 목표 → 충전 → 이탈 대기 순서로 웹 시연한다.

번호는 현재 종류별 객체 목록의 순서이며 해당 지도 버전에 대해 정확한 ID로 변환된다. 객체 삭제 등으로 지도 버전이 바뀌면 과거 코드를 그대로 적용하지 못한다. 현재 지도에서 재생성 또는 코드 수정·재검증이 필요하다. 실행 중 적용은 차단하며 일시정지가 필요하다. 적용하면 다른 기체의 임무·목표·객체는 보존하지만 전체 실행 위치·예약은 초기화된다.

## 한계

현재 지원하는 자연어 임무는 한 기체의 한 안전모 픽업·한 작업자 전달이다. 일반 LLM 바이브 코딩, 여러 임무 묶음, 임의 JavaScript/Python 실행은 제공하지 않는다. JSON은 제한된 구조화 임무 형식이다. 기체·안전모·작업자는 출발 층이 같아야 하며 경로가 확보되지 않으면 주행이 차단된다. 복잡한 지도 전체에서 경로 존재·교착 해소를 보장하지 않는다.

미착용은 사용자 진술로 처리하며 영상 YOLO 감지나 신원 확인이 아니다. 집기/전달은 가상 행동과 payload 상태 전환이며 실제 팔 동작·보호장구 착용·물리 물체 이동은 아니다. 합성 카메라·로컬 웹 시뮬레이션 범위이고 Unity/CARLA/Gazebo·실제 Pi5 실행은 미연결이다. 배포하지 않았다.
