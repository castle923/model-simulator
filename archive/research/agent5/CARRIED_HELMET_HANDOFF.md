# 안전모 운반·작업자 보유 상태 인계

2026-10-14. 복사본 로컬 구현만 수행했다. 원본·운영 사이트·DB·원격 push·배포는 변경하지 않았으며 사용자 편집 브라우저 탭도 제어하지 않았다.

## 실제 동작

1. 실행 시작은 모든 안전모가 편집 지도 원래 위치의 `ground` 상태다.
2. 정확한 helmetId의 외곽 접근점에서 집기 대기 후 `{kind:'robot',robotId}`로 변경한다. 바닥 안전모는 렌더에서 사라지고 기체에 부착된 작은 운반 심볼이 pose·yaw·층을 따라 움직인다.
3. 정확한 workerId 외곽에서 전달 대기 후 `{kind:'worker',workerId}`로 변경한다. 기체에서 해제되어 해당 작업자 손 위치에 표시한다. 작업자 보유는 **착용 완료가 아니다**.
4. 기체는 기존 목표 주행→공용 충전 대기→충전→이탈을 계속한다. 전체 자율 순찰/PPE 자동 인식/30% 충전 트리거는 이번에 구현하지 않았다.

## 공통 상태 계약

- `lib/scene-runtime.ts`의 `helmetOwnership(scene,poses)`가 helmetId별 ground/robot/worker 소유권의 권위 상태다. poses 객체를 키로 한 WeakMap으로 실행 수명을 구분한다.
- `payload`와 `payloadHelmetId`는 소유권의 파생 값이다. 안전모 또는 소유자가 삭제되면 정리된다. 소유자 삭제로 복원될 때에는 편집 원래 위치의 ground 상태다.
- `runtimeEntities(scene,poses)`는 소유 상태에서 지도·정면 카메라에 공통으로 사용할 렌더 엔티티를 만든다. 편집 scene 자체를 변경하지 않는다.
- 지도와 `lib/front-projection.ts`가 동일 상태를 읽는다. 선택 기체 자신의 안전모는 정면 카메라의 운반 배지로 표시하며, 타 기체의 운반 안전모와 작업자 손의 안전모는 높이가 있는 심볼로 투영한다.
- Canvas `dataset.world.helmetOwners`와 실행 종료 기록의 `helmetOwners`에 같은 상태를 넣는다. 종료 스냅샷은 reset 전에 복사하여 이후 편집으로 바뀌지 않게 한다.

## 수명·중복 정책

- 일시정지와 실행 종료: 마지막 운반/보유 상태를 유지한다.
- 기체 초기화, 새 실행, 지도 편집·삭제·Undo, 새로고침: 새로운 poses/world를 만들고 편집 원래 위치의 ground로 복원한다.
- 같은 안전모를 둘 이상의 기체에 배정하거나 같은 작업자에게 중복 전달하는 임무는 `planScene`에서 명확히 거부한다. runtime도 이미 집힌 안전모와 잘못된 전달 소유권을 검사해 오류 정지한다.
- 단일 기체는 락 표시·선택 목록·추가·hit-test에서 제외한다. 락 데이터는 삭제하지 않고 다중 전환 시 다시 사용한다. 단일 통로예약/다중교착 검사 생략은 유지한다.

## 충돌·표현의 한계

- 계획 경로는 편집 원래 안전모 위치를 보수적으로 장애물로 계속 취급할 수 있다. 화면에서 집힌 안전모가 사라졌다고 실센서 ghost 장애물을 자동 해결한 것은 아니다.
- 운반·손 보유 심볼은 교육용 축소 표시다. 실제 매니퓰레이터 관절, 그리퍼, 장비 질량, 운반물의 3D swept volume, PPE 착용 인식은 검증하지 않았다.
- 사람·안전모 외곽 접근과 연속 직선/원호 충돌 검사는 유지했다. 실제 엔진·Pi5·센서·엘리베이터 제어는 여전히 미연결이다.
