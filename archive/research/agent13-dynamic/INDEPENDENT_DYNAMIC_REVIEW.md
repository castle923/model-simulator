# Astra 13 동적 주행 독립 검토 — PASS with limits (LOCAL ONLY)

2026-10-14. Agent14 동결 소스에서 별도 검사 3개를 직접 작성·실행하고 기존 신규 회귀 2개를 직접 실행했다. **검증한 로컬 범위에서 새 BLOCK 없음. 합성 감지 → 실제 경로 변경 → 우회 → 원래 목표 방문 → 임무/충전/이탈 완료가 확인된다.** 임의 모든 배치의 무교착, 실센서 인식, 공개 배포 반영은 검증하지 않았다.

제품 작성자는 Agent14다. 본인은 제품 파일, Git stage/commit/push, 클라우드/API/배포, 원본 서비스, 사용자 브라우저를 변경하지 않았다. 이번에 작성한 파일은 outputs/agent13-dynamic 및 research/agent13-dynamic 안에만 있다. 공개 재배포 여부는 사용자 결정으로 남긴다.

## 독립 주행 검사

`outputs/agent13-dynamic/independent-motion.mjs` / `.log`는 구현자 검사와 다른 dt 순서(.011/.027/.047/.019)를 사용한다. route ID/points만 별도로 직렬화해 카운터나 상태 문구 변화와 무관하게 실제 경로 형상 변경을 검사한다. 각 기체의 원래 goal 방문 여부와 전체 완료를 따로 기록한다.

| 입력 | 속도 | 완료 가상시간 | 최소 endpoint 간격 | 상대 이동의 최소 chord 간격 |
|---|---:|---:|---:|---:|
| 기본 동적 예시 | 0.1m/s | 170.675s | 0.594360m | 0.594360m |
| 기본 동적 예시 | 0.35m/s | 51.896s | 0.593161m | 0.593156m |
| 기본 동적 예시 | 0.8m/s | 22.995s | 0.606991m | 0.606974m |
| 영구 정지 기체 우회 | 0.8m/s | 22.371s | 0.587858m | 0.587818m |
| 사용자 편집 지도 | 0.35m/s | 70.181s | 0.522159m | 0.522128m |
| 전진 자동차 2대 | 0.35m/s | 77.149s | 0.607622m | 0.607603m |
| 별도 열린 공간 대각 교차 4대 | 0.8m/s | 34.093s | 0.490016m | 0.490016m |

모든 활동 기체가 원래 목표를 실제 방문하고 완료했다. 영구 정지 R2는 phase를 임무 완료로 고정한 테스트에서 매 tick 이동거리 0을 확인했다. 다른 기체를 몰래 이동시키거나 삭제하지 않고 R1이 경로를 바꿔 통과했다. 모든 입력 Scene은 불변이었고 종료 때 예약과 lift가 해제됐다.

전진 자동차는 매 tick 이동거리≤speed*dt, 각변화≤speed*dt/minRadius, 전진 내적 양수, 정지 시 회전 없음으로 검사했다. 기존 신규 회귀에서 재계획된 모든 car 경로 segment의 곡률/전진도 직접 재실행 확인했다. chord 최소 간격은 상대 선형 이동의 독립 검사이며 자동차 원호 간의 완전한 연속 최적화 증명은 아니다. 구현은 짧은 tick과 추가 0.002m 원호 안전 여유를 사용한다.

본인 motion 입력의 최대 step 실행 시간은 최종 측정에서 14.502ms 이하였다. 실제 브라우저 렌더/입력 지연 측정은 이 결과와 별개다.

## 임무·센서·좁은 통로 상태 검사

`outputs/agent13-dynamic/independent-state.mjs` / `.log`:

- 안전모 집기 후 운반 중 실제 replan을 유발했다. deliver 인덱스 66→67 변경에도 ground→robot→worker 전이는 각각 한 번이며 정확한 대상 소유권을 유지했다. pickup 이후 payload가 초기화되지 않았다.
- 이어서 2층 원래 목표(8,1)를 방문하고 floor 1→2→1, 충전·이탈·완료까지 51.2초에 종료했다. pickup/deliver/queue/charge/exit 인덱스 범위를 매 tick 확인했다.
- 진행 중 progress가 있는 경로에 불가능한 replan을 요청하고 실패 전후 route와 Runtime 전체 JSON 동일성을 확인했다. 부분 경로/인덱스/배터리 반영 없음.
- 다른 기체가 세 번째 기체의 중심 시선을 가리는 관측, 그 기체 이동 후 새 관측, 가려진 추적 기억, 기체 삭제와 새 run 관측 상태 초기화를 확인했다.
- floor=0인 공용 lock을 사용하는 물리적으로 좁은 통로를 두 기체가 반대 방향으로 진행하고 route 배열을 뒤집었다. 매 tick lock 내부 점유 최대 1대, 점유 기체와 owner 동일, 두 기체 모두 통과, 종료 후 owner 없음. 41.912초에 완료했다.

센서의 range/FOV/층/static 가림/빈 이전 위치 제거/TTL은 구현자 신규 회귀도 별도 직접 실행했다. 소스를 읽어 shared FOV, 3.6m range, .15s sample, 1.2s TTL, 센서와 별도 전역 안전 검사를 대조했다. 중심 ray의 2D 가림이며 픽셀/부분 BBOX 인식이나 물체 높이를 해석하는 실제 시각 인식이 아니다. 문서가 이 제한을 명시한다.

## 실패·계산량 제한

`outputs/agent13-dynamic/independent-bounded-failure.mjs` / `.log`:

실제로 우회할 공간이 없는 통로에서 R2를 영구 정지시켰다. R1 실패 횟수는 가상시간 .1/1.0/2.6/4.9/7.9/11.6초에서 1→6으로 증가하고 이후 100초까지 더 재시도하지 않았다. 마지막 30초 pose가 동일했고 '전역 안전 정지 / 6회 소진' 상태를 유지했으며 false completion 없음. 최소 간격 0.490091m, 최대 tick 23.493ms.

첫 테스트 구성에서는 Q2가 추가 벽에 겹쳐 정상 정적 계획 거부가 발생했다. 이는 제품 결함으로 보고하지 않았고 테스트의 Q2를 실제 빈 공간으로 옮겨 동적 실패 상태를 검사했다.

`test-dynamic-navigation.mjs`의 100객체 재계획 스트레스를 본인이 다시 실행한 결과 55.39ms였다. 탐색의 14,000노드/약55ms 공유 예산, 전역 .35s 및 기체별 .9s 이상 간격, 실패 backoff를 소스로 확인했다. 시간 확인이 매64노드이고 부수 작업은 별도이므로 55ms는 엄격한 실시간 deadline이 아니다. main-thread 동기 계산이므로 최대 허용 입력에서도 렌더링 프레임 손실이 전혀 없다는 보장은 하지 않는다. 현재 문서도 이 제한을 밝히고 있다.

## 소스·UI 연결 및 동결 증거

SceneLab 소스에서 새 예시 버튼은 사용자 클릭 시에만 commit한다. 실행 routes는 Worker의 정적 원본을 structuredClone한 activeRoutes이며 새 run은 다시 복제한다. 프레임에서 변경 경로, 감지 IDs, route revision을 같은 실행 pose/시간과 함께 그리는 경로를 확인했다. UI 실제 클릭/녹화/새 실행 복원 검증은 root 별도 담당이며 본인이 대신 실행했다고 주장하지 않는다.

확인한 소스 13개 SHA-256을 `outputs/agent13-dynamic/reviewed-source-hashes.json`에 남겼다. 전달받은 Worker SHA-256과 실제 파일이 일치한다:

`1A1C6FC1BBC22490118C1D3AAA71D87319B72C5D8BF3D675762FD07B12E9906E`

`docs/DYNAMIC_NAVIGATION.md` 및 38행 REQUIREMENTS_STATUS의 동적/ghost 변경이 실제 구현 범위를 넘겨 실센서·실물·완전 무교착으로 표현하지 않는지 읽기 확인했다. 자동순찰/PPE/재고/30% 정책의 미구현 상태도 유지됐다.

## 최종 판정

**LOCAL PASS with limits. 독립 검사 범위에서 추가 수정이 필요한 BLOCK은 없다.** 이번 결과는 검증한 지도·속도·상태 전이의 근거이며 모든 지도의 해 존재/완주, 실제 센서나 차량 안전, UI 실시간 성능 보장, 공개 사이트 반영을 의미하지 않는다. 현재 배포는 변경하지 않는다. 향후 재배포는 사용자 결정과 그 시점의 소스/빌드/배포 검증에 따른다.
