# 1차 목표 자율주행 기능 도입 검토 보고서

작성일 2026년 10월 14일. 대상은 4인 학생팀의 라즈봇 V2와 Raspberry Pi 5 시연 프로젝트다. 8번 센서·ROS 2 기술 보고서에서 1차 목표에 필요한 기능만 추렸다. 아래 도입안은 설계 검토이며 실제 센서 연결이나 실물 주행 시험 완료를 뜻하지 않는다.

**1차 목표는 한 번의 명령으로 출발하고, 장애물을 회피하여 목적지에 도착한 뒤, 지정한 복귀점으로 돌아와 대기하는 것이다.** 이후 사용자가 정한 공용 충전소를 복귀·대기점으로 사용할 수 있다. 충전소로 돌아오는 것과 실제 전기 충전·자동 도킹은 별도 기능이다. 성공률·허용 시간·거리·오차의 목표치는 팀원과 강사 협의 후 확정한다.

## 1차 목표에 포함할 기능

| 구분 | 필요한 기능 | 프로젝트에서 하는 일 | 적용 조건과 판단 |
|---|---|---|---|
| 필수 | 기체 구동과 비상 정지 | 전진·회전·감속·정지 명령 실행 | 실제 보드 제어 API와 정지 동작 확인. 웹 이동 모형과 실물 제어를 구분 |
| 필수 | 주변 거리 측정 | 벽·랙·새 장애물의 거리 확인 | 2D LiDAR 한 종류를 우선 비교. 현재 보유·장착·드라이버 시험은 미확인 |
| 필수 | 실측 위치 추정 | 현재 위치와 방향을 추정하여 지도에서 길 찾기 | wheel odom·TF 확인, IMU 융합 검토. 모터 PWM 명령을 실측 이동거리로 취급하지 않음 |
| 필수 | 지도 생성 또는 지도 등록 | 공장 공간을 주행 가능한 지도로 준비 | SLAM Toolbox 등은 LaserScan·TF·odom 등 입력 조건을 확인한 후 도입. 기존 센서만으로 즉시 SLAM 가능하다고 판단하지 않음 |
| 필수 | 목표·복귀 경로 계획 | 목적지와 복귀점까지 경로를 각각 계산 | ROS 2 Nav2 후보. 지도·위치 추정·기체 크기·구동 제약·컨트롤러가 함께 필요 |
| 필수 | 동적 장애물 회피와 재계획 | 주행 중 새 장애물을 만나면 가능한 다른 경로 탐색 | 안전한 우회 경로가 없으면 정지·대기·재계획·실패 보고 허용. 무조건 회피 성공을 보장하지 않음 |
| 필수 | 한 명령 임무 상태 관리 | 출발부터 왕복 완료까지 한 번에 실행 | 이동 중·회피 중·목적지 도착·복귀 중·대기·실패 상태를 구분 |
| 필수 | 근접 감지와 통신 watchdog | 가까운 장애물·센서/제어 통신 단절에 대응 | 기존 초음파 활용 가능성 확인, 필요 시 ToF/범퍼 보완. 제어기 자체의 정지 시험 필요 |
| 시연 검증 | 선택 기체 전방 카메라 | 회피 과정과 목적지 도착 장면 관찰 | 영상과 pose에 기체 ID·실행 ID·시각·출처 표시. CPU 성능은 측정 |
| 1차 AI 항목 | YOLOv8n 객체 탐지 | 사람 등 장애물 종류를 해석하는 보조 정보 | 기본 모델의 클래스 확인. 단안 BBOX만으로 정확한 거리·안전 정지를 결정하지 않음. 안전모 미착용 판별은 별도 학습 과제 |
| 시연 검증 | 실행·센서 로그와 재생 | 실패 원인과 회피 성능을 팀원과 확인 | pose·scan·영상·명령·상태 전환을 같은 시간축으로 기록. rosbag2 등 검토 |
| 다중 기체 확장 | 통로·충전 대기점 예약 | 2대 이상이 좁은 통로·복귀 공간에서 충돌하지 않도록 순서 제어 | 먼저 단일 기체 왕복을 통과한 뒤 적용. 기체별 namespace·TF·ID 필요 |

## 센서 구성과 호환성

**최소 도입 방향은 기존 RGB 카메라 + 2D LiDAR 한 종류 + 신뢰할 수 있는 이동거리·방향 측정이다.** RGB는 물체 종류, LiDAR는 거리, odom/IMU는 기체 움직임을 담당하므로 서로 완전히 대체하지 않는다.

| 구성 | 1차 역할 | 현재 판단 | 선행 확인 |
|---|---|---|---|
| 기존 USB RGB 카메라 | 전방 관찰·YOLO 입력 | 기존 부품 활용 우선 | Ubuntu 실물 영상 수신, 카메라 보정, 해상도·노출·지연 |
| 기존 초음파 | 근접 거리 보조 | LiDAR 대체로 단정하지 않음 | 유효 범위·사각지대·샘플 주기·board API |
| RPLIDAR A1/C1 또는 LD06/LD19 | 2D 거리·지도·회피 | 공식 ROS 2 드라이버가 있는 비교 후보 | 정확 모델·전원·USB/UART 변환·ARM64/Jazzy 빌드·실수신. 구매 확정 아님 |
| 바퀴 인코더 | 실측 이동거리와 속도 | Raspbot count/속도 읽기 API 미확인 | 모터·보드 모델, firmware, 피드백 API. 없으면 추가 하드웨어 또는 다른 위치 추정 방법 필요 |
| IMU | 방향·회전·미끄러짐 추정 보조 | 추가 후보 | 센서 모델·전압·I2C/SPI/USB·시간 보정·공분산. IMU만으로 안정적인 실내 절대 위치를 얻는다고 보지 않음 |
| ToF·범퍼 | 근접·낮은 장애물·접촉 감지 | 필요 시 보완 | 전압·핀·장착·Range/접촉 상태 연결기 |

ROS 2 Jazzy의 ARM64 지원이 센서의 Pi5 호환을 자동 보장하지 않는다. ROS 2 지원 문구, 드라이버 빌드, 실제 수신, 장시간 성능은 각각 확인해야 한다. Pi5 USB 전원 예산은 여러 센서의 합산 소비전력과 비교하며, 필요 시 별도 정격 전원을 검토한다.

## 주행 프로그램 역할

| 프로그램·기술 | 1차 기능 | 필요한 입력·조건 |
|---|---|---|
| ROS 2 Jazzy | 센서·제어·기체 상태 연결 | Ubuntu 24.04 우선 후보. 팀 환경 확정 필요 |
| Gazebo Harmonic | 장애물·센서·주행 시험 환경 | 실제 구동 모델·센서·ROS 연결기 필요. 웹 pose 프록시만으로 실제 주행 검증을 대체하지 않음 |
| SLAM Toolbox | 2D 지도 생성과 위치 추정 구성 | LaserScan·TF·odom 등 유효 입력과 설정 |
| robot_localization | odom·IMU 등 상태 융합 | 실제 측정값·시간·공분산·TF |
| Nav2 | 목표 주행·장애물 반영·경로 재계획 | 지도·위치 추정·센서·기체 footprint·컨트롤러 |
| YOLOv8n | 시각 객체 분류 보조 | 카메라 영상·검증된 가중치·CPU 런타임. 강사 데이터의 클래스 확인 |
| rosbag2 | 실행 상태·센서 기록 | 기체별 토픽과 시뮬레이션/실측 시각 구분 |

기준 후보는 Ubuntu 24.04 + ROS 2 Jazzy + Gazebo Harmonic이다. Ubuntu 22.04 검증은 Humble + Fortress 등 별도 호환 조합으로 분리한다. Classic 11과 Fortress는 같은 프로그램이 아니다.

## 한 번의 명령으로 수행할 순서

| 순서 | 임무 상태 | 진행 조건 |
|---|---|---|
| 1 | 준비 확인 | 지도·위치·거리 센서·제어·배터리·복귀점 확인 |
| 2 | 목적지 주행 | 유효한 경로를 따라 이동 |
| 3 | 장애물 대응 | 감속·거리 확보·우회·재계획. 우회 불가 시 안전 대기 또는 실패 보고 |
| 4 | 목적지 도착 | 팀이 정한 위치 오차와 정지 조건 만족 |
| 5 | 복귀 주행 | 출발점 또는 지정 충전 대기점까지 새 경로로 복귀 |
| 6 | 완료 대기 | 정지 확인, 공간 점유·예약 상태 정리, 실행 결과 기록 |

후진 금지·자동차형 U턴을 1차부터 적용할지는 팀이 결정한다. 적용한다면 최소 회전 반경과 차체 크기를 반영하고, 복귀·충전소 출구에서도 같은 제약을 지킨다. 회전 공간이 없는 배치를 경로 불가로 판단하는 것은 정상 결과다.

## 단일 기체 이후 다중 기체에 추가할 기능

| 기능 | 목적 | 검증할 조건 |
|---|---|---|
| 기체별 ID·namespace·TF | 센서와 명령 혼선 방지 | R1/R2 등의 scan·odom·camera·명령이 섞이지 않음 |
| 통로 예약과 대기 | 좁은 통로 동시 진입 방지 | 진입 순서·완전 이탈 후 해제·통신 단절 시 대응 |
| 단일 복귀·충전 공간 예약 | 공용 공간 중복 점유 방지 | 1대 점유 중 다른 기체가 지정 대기점에서 대기 |
| 예약 만료와 복구 | 소유 기체가 끊긴 경우 대응 | 위치가 불명확한데 예약만 자동 해제해 충돌시키지 않음 |

1cm 선행 규칙은 웹 시연의 판정 규칙이다. 실물에서는 위치·시각 오차를 측정한 뒤 여유 거리와 동률 처리 기준을 결정한다. 소수점 좌표 표시가 1cm 실측 정확도를 뜻하지 않는다.

## 1차 완료 판정표

수치는 팀·강사가 합의할 항목이다. 임의의 합격 숫자를 확정하지 않았다.

| 시험 | 확인할 결과 | 목표치 |
|---|---|---|
| 장애물 없는 왕복 | 한 명령으로 목표 도착·복귀·대기 | 성공률·횟수 협의 |
| 고정 장애물 우회 | 충돌 없이 목적지와 복귀점 도달 | 최소 여유 거리·시간 협의 |
| 새 장애물 등장 | 감속·우회·재계획 | 반응 시간 협의 |
| 우회 불가능 | 무리한 진입 없이 정지·실패/대기 상태 | 정지 거리·도움 요청 조건 협의 |
| 위치·센서 유실 | 오래된 위치로 계속 주행하지 않음 | timeout·복구 조건 협의 |
| 통신 단절 | 로컬 제어기에서 정지 | 정지 지연 협의 |
| 배터리 부족 | 왕복 가능 여부 확인 또는 임무 거절 | 예비 잔량·소비 모델 협의 |
| 영상·센서 재생 | 실행 장면과 상태 원인 확인 가능 | 영상 지연·로그 누락 허용치 협의 |
| 다중 통로·복귀점 | 중복 점유·교착 없이 처리 | 단일 기체 통과 후 별도 목표 협의 |

실제 배터리 측정 API가 없으면 웹의 가상 배터리를 실물 임무 승인 근거로 사용하지 않는다. 교육용 LiDAR·Nav2 기능은 산업 안전 인증 시스템과 구분한다.

## 1차에서 제외할 내용

양팔·그리퍼 제어, 안전모 집기와 전달, RGB-D 기반 집기 좌표, 힘/토크·촉각, 3D LiDAR와 3D SLAM 연구, 휴머노이드 시연학습, 엘리베이터·층간 이동은 이번 1차 필수 범위에서 제외한다. 안전모 미착용 탐지 학습은 2차 보호장비 전달 목표와 연결해 별도 검증한다. QR/AprilTag 도킹 표식은 필요성이 확정될 때 보조 기능으로 검토하며 1차 필수 센서로 강제하지 않는다.
