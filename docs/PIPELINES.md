# 파이프라인
## P1 개발·검증
요구사항/Issue → 담당·변경 파일 지정 → `codex/<주제>` 브랜치 → 구현 → 관련 회귀 → 30개 검사+타입 → 프로덕션 빌드 → Astra 또는 팀원 독립 검토 → PR → 사람이 병합.

GitHub Actions `.github/workflows/ci.yml`은 push/PR/수동 실행 시 의존성 설치 → Worker 생성 → 회귀/타입 → 빌드를 실행하고 검사·빌드 자료를 보관합니다. 배포 토큰은 사용하지 않으며 운영 사이트/DB를 변경하지 않습니다. 이 CI는 웹 코드를 검사하며 실물 안전성을 승인하지 않습니다.

## P2 웹 실행
기체 프리셋/장비/속도 → 공통 장면 편집 → 입력 검증 → Worker 정적 임무 경로 → 실행 중 합성 관측/기억 만료 → 동적 우회 또는 안전 대기 → 통로/충전 예약 → 기체별 완료 → 로컬 실행 기록/JSON/녹화.
주요 소스: `scene-local`, `scene-navigation`, `planner`, `scene-runtime`, `scene-sensor`, `scene-locks`, `robot-customization`, `front-projection`.

## P3 명령·오류 분석
자연어(지원 문법) 또는 JSON → 대상 기체/지도 버전 확인 → 검증 → 명시적 적용 → 주행 → 결과 비교 → 의견 기록 → 수정·재검증.
force-direct만 회피·충돌정지·예약을 생략합니다. 형식/경계 검증은 유지합니다. 안전 외곽 침범은 실물 충돌 측정이 아니며 정상 코드로 내보내지 않습니다. 정상 복귀는 실험 플래그를 제거합니다. 의견 저장은 자동 학습/자동 코드 수정이 아닙니다.

## P4 팀 공유·실물 연결(후속)
현재 `/`의 지도/기록은 브라우저별 저장입니다. `/legacy`의 서버 협업 소스와 별개입니다. 공동 지도 동기화, WebRTC/TURN 다중 PC, timestamp 댓글, 인증/작성자 보호, DB 어댑터는 별도 운영 검증이 필요합니다.
Unity/CARLA/Gazebo 및 ROS2/Pi5 연결은 외부 실행기 → 좌표/시간/기체ID handshake → 상태/영상 → 웹 표시로 설계하며, 실제 엔진과 실물 모터 검증 게이트를 분리합니다.

## P5 수동 릴리스
검사+빌드+브라우저 결과 → 정확한 커밋·아티팩트 확인 → 별도 배포 승인 → 기존 Site ID/공개범위 보존 → 버전 저장/배포 → 운영 URL 재확인. GitHub 저장소에는 자동 배포 워크플로가 없습니다. 이 보존 작업은 기존 사이트의 변경 요청이 아닙니다.
