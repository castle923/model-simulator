# MECHANIC 팀 시뮬레이션 랩

4인 학생 로봇 프로젝트를 위한 웹사이트. 팀원은 GPT 계정 없이 닉네임으로 입장합니다.
관리 소유자는 Sites의 사용자 계정에 유지됩니다. 공개 URL이므로 링크 자체가 접근 제한은 아닙니다.

## 구현 기능

- 로컬 브라우저에 보관되는 무작위 작성 키. 동일 닉네임도 다른 작성자로 처리.
- 작업 게시판, GitHub 참고 링크, 작성자 한정 수정, 이전 버전 보존, 오래된 버전 수정 거부.
- 새 파일 ID·SHA-256을 사용하는 첨부 업로드. 덮어쓰기·기존 자료 삭제 API 없음.
- 서버 DB의 unique index로 전체 하나의 활성 발표 실행만 허용.
- 한 발표자 → 관찰자들의 WebRTC 영상 공유. 별도 브라우저에서 수신 검증.
- 내장 2D Raspbot V2 근사 외형, 격자 경로 계획, 장애물 여유 공간, 목적지·복귀 실험.
- 외부 Unity 창 화면 선택(getDisplayMedia), MediaRecorder 녹화, 로컬 다운로드 및 서버 저장.
- 실행별 댓글과 영상 시점(초), 녹화 영상의 해당 시점으로 이동.
- 실행 당시 데이터·코드 버전 문자열 기록. 외부 Unity 파일 내용 자체를 고정/검증하는 기능은 아직 없음.

## 한계

- 내장 실험은 2D 운동학/가상 데이터. Unity, 실제 로봇, YOLO 실행이 아님.
- 실제 Pi 연결·자동 발견·모터 제어는 미구현. `ROBOT_AND_UNITY_REVIEW.md` 참조.
- 현재 WebRTC STUN 직접 연결. 서로 다른 NAT/학교 방화벽 환경의 연결은 미검증.
  연결이 불가능한 네트워크에는 TURN 서비스와 자격증명이 필요. 비공식 공개 TURN을 임의 사용하지 않음.
- 영상 소리는 현재 전송하지 않음. 영상만 공유. 사용자가 화면 선택을 취소하면 시작하지 않음.
- 관찰방의 연결 신호·댓글 갱신은 약 2~5초 polling. 영상 자체는 WebRTC 경로.
- 실시간 영상 되감기는 지원하지 않음. 종료 후 녹화 저장 시점부터 댓글 seek 가능.
- 녹화는 발표자 메모리에 먼저 보관. 탭을 닫기 전 다운로드/서버 저장 필요. 75MB에서 녹화만 종료.
- 파일당 최대 80MB. 서버는 스트리밍 해시·저장하며 실행 파일은 다운로드만 제공.
- 브라우저 키 삭제/다른 PC에서는 기존 글의 작성 권한을 잃음. 닉네임은 신원 인증이 아님.
- GitHub 자동 병합·파일 수정 없음. 팀원 작업이 우선이며 PR 링크로 검토.

## 실행/검사

```powershell
node scripts/run-framework.mjs dev
node node_modules/typescript/bin/tsc --noEmit
node scripts/test-hub.mjs
node scripts/run-framework.mjs build
```

`test-hub.mjs`는 로컬 DB에 `[자동검증]` 데이터를 작성합니다. 운영 URL에는 실행하지 마세요.
로컬 D1 마이그레이션은 Sites skill의 절차를 따릅니다. 운영 DB와 로컬 DB는 별도입니다.
게시물/실행/댓글은 D1, 파일/녹화는 R2, 웹 실행은 Cloudflare Worker/Vinext입니다.

## 배포 검토 상태

- Sites 등록 ID는 `.openai/hosting.json`에 저장. 사용자 요청에 따라 공개 접근 설정.
- Supabase 기존 `wvzvyulvaarbpibftojr` 프로젝트는 사용자 최종 승인 후 삭제했고 목록에서도 제거 확인.
- 새 Supabase 프로젝트: 같은 조직·서울 리전 선택 받음. 필수 get_cost 도구가 UNAVAILABLE여서 생성 안 됨.
- Vercel 연결 도구는 teams=[] 반환. 배포할 범위 미확정. Vercel 배포는 수행하지 않음.
- 현재 Cloudflare DB/R2 binding이 있으므로 Vercel에 그대로 옮길 수 없음.
  Vercel 전환 시 Next.js + Supabase/외부 저장소 adapter로 변경 필요.

## 팀 운영 원칙

원본/팀원 변경 우선. 별도 폴더에서 구현했고 기존 `simulation-prep` 내용은 수정하지 않았습니다.
서브에이전트가 팀원 파일·Pi 설정을 임의 변경하지 않도록 장치 제어를 본 사이트와 분리합니다.
실물 구동은 단일 조작자/명령 만료/로컬 watchdog/물리 비상정지를 검증한 후 별도 활성화합니다.

## 공간 편집 및 충전소

환경 편집에서 가로·세로 1~20m, 출발점, 작업 목적지, 충전소 한 곳을 설정합니다. 상자·콘·작업자·안전모의 위치/크기/회피 여부를 설정하고 적용한 물체를 드래그할 수 있습니다. 첫 경로와 목적지→충전소 경로를 모두 검증한 후 실행하며, 충전소 도착 후 대기합니다. 실제 충전/도킹은 구현하지 않습니다. 기존 JSON에 station이 없으면 출발점을 충전소로 사용합니다.

환경은 브라우저별 localStorage에 저장되어 다른 팀원 환경을 덮어쓰지 않습니다. JSON 내보내기/불러오기와 게시판 첨부로 공유합니다. 주행·방송 중 환경 편집이 잠기며 내장 시뮬레이터 방송 시작 시 environment-snapshot.json을 실행에 첨부합니다. 정적 2D 근사이며 물체 100개까지 지원합니다. CARLA/Unity용 파일 변환은 별도 구현이 필요합니다. CARLA 검토는 CARLA_REVIEW.md를 참조하세요.

## 공장 다중 기체 환경 편집

공장 환경 편집에서 랙·벽·팔레트·상자·콘·작업자·안전모를 추가하고 가로/세로 크기와 위치, 회피 여부를 설정합니다. 공장 지도는 8×4m, 대기선/경유점/주차 위치는 고정입니다. 모든 환경요소를 반영한 경로를 재계산하며 막힌 배치는 적용되지 않습니다. 기체 접근·대기·주차 예약 영역을 보존합니다. 지도에서 물체를 드래그해 놓으면 검증 후 적용합니다. 주행 시작 후에는 초기화 전 편집을 잠급니다. 환경은 브라우저별 mechanic-factory-v1로 저장하고 JSON으로 공유합니다.

일반 글자 15px, 설명/보조 글자 13px 이상, 버튼 최소 높이 40px로 가독성을 개선했습니다.

## CPU 및 팀 환경 검토

Unity/CARLA/Gazebo 선택, CPU·무화면 프로필, 카메라 포함 Gazebo SDF 내보내기를 추가했습니다. WSL Ubuntu의 실제 Gazebo 640×480 이미지를 JPEG 품질 85로 인코딩해 웹 카메라 패널에 최대 2fps로 수신합니다. 세션 작성자는 현재 지도를 Gazebo에 적용하고 상부 또는 선택한 기체의 정면 카메라 시점을 고를 수 있습니다. 정면 시점에서 위치 동기화를 켜면 웹 주행 좌표를 약 1초 간격으로 Gazebo 프록시에 적용해 카메라가 따라갑니다. 기체 추가·삭제와 물체 배치 변경은 장면을 다시 적용합니다. 이는 웹 시뮬레이션 좌표를 시각화한 것이며 실제 Raspbot/Pi5 제어·물리 주행은 아닙니다. cpu-simulation-prep/README.md에서 조건과 실행 예를 확인하세요. ROS 2 학습 자료와 Ubuntu 24.04/Jazzy/Harmonic, 22.04/Humble/Fortress 호환표는 팀 환경 연구 패널에 표시하며 팀 확정으로 저장하지 않습니다.

## 웹 2D 주행 속도

단일 기체와 공장 전체 기체에 속도 트랙바를 제공합니다. 기본값은 0.35m/s이며 0.10~0.80m/s를 0.05m/s 단위로 선택합니다. 표시값은 소수점 두 자리입니다. 주행 중에도 속도를 변경할 수 있으며 현재 위치·경로·통로 락·충전소 예약·일시정지 상태는 유지합니다. 공장 초기화는 선택한 속도를 유지합니다. 화면 공유 관찰자는 속도를 읽을 수 있고, 주행 제어권이 있는 발표자가 변경합니다. 환경 편집 잠금과 속도 제어권은 별개입니다.

공장 주행 전 속도를 바꾸면 전체 경로·충전 대기열 시연을 복제 상태에서 먼저 검증하고 성공한 경우에만 반영합니다. 같은 속도를 기체 이동, 진입선 도착 시각, 충전소 대기시간과 가상 배터리 소비량 계산에 사용합니다. 가상 충전 속도는 4.00%/초로 유지합니다. 이 트랙바는 웹 2D 시연에만 적용하며 실제 Pi5/Raspbot 또는 Gazebo의 주행 속도를 설정하지 않습니다. `node --experimental-strip-types scripts/test-fleet-speed.mjs`로 최저·최고 속도, 2대·4대 충돌 여유, 충전 대기열, 1cm 선착순, 주행 중 변경과 잘못된 속도의 원자적 거부를 검사할 수 있습니다.
